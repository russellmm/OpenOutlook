# OpenOutlook implementation status

This is a **development prototype, not the approved first release**. The full requirements and release gates remain in `PRODUCT_REQUIREMENTS.md` and `DESIGN_SPEC.md`.

## Implemented now

- Reproducible .NET 8 solution with Avalonia 11.2.3 desktop shell.
- Copied owner's `PstCore` source into `src/PstCore`, no private archives or build outputs.
- Read-only PST archive open/detach, folder list, message summaries and plain-text or limited safe HTML body preview. The folder tree uses the archive's display name and shows mailbox folders directly, hiding empty PST bookkeeping folders; unread counts appear beside the archive and folders. The message list is a virtualized table with movable, resizable, sortable paperclip, From, Subject, Received and Size columns. It defaults to collapsible Outlook-style calendar date sections; clicking a sort column switches to a flat, globally sorted list, and the Group by date control restores the sections. Column order/widths and the three pane proportions persist in local view settings and were verified across a headless restart. Missing sizes in the PST folder index are filled from lightweight message metadata; an eight-folder summary cache speeds repeat visits. Reading the largest supplied sample folder (2,690 messages) took about 255 ms in a local core benchmark; that is not a full UI latency measurement. A selected by-value attachment can be exported to a **new** local file with strict filename/size checks, a private 0600 file mode on Unix, an atomic temporary-file move and no overwrite; it never modifies the archive. All reader work runs outside the UI thread and is serialized; source archives are never opened writable. The export path now calls a bounded PST reader that checks declared external-block sizes before allocating and limits the message/attachment heaps to 1 MiB each; it accepts cancellation between block reads and fails closed on ambiguous attachment subnodes. It still buffers permitted attachment bytes in memory and has not been fidelity-tested against all supplied attachment variants.
- Persistent light/dark theme, a four-color high-contrast accent palette and text-size controls in an Appearance Options dialog (preferences stored in XDG config); rudimentary Outlook-like three-pane layout. The toolbar wraps and panes share available width at the 850-pixel minimum window size. Compose controls do not exist yet, and the broader account/Junk options are not implemented.
- Portable junk sender/optional-rule matcher plus per-account opt-in settings, durable JSON storage and explicit legacy configuration preview/import; UI now offers a **read-only legacy config preview** showing counts/rule summary without revealing keyword strings or enabling cleaning. **Not connected to any live account**, never moves/deletes mail.
- Microsoft Graph **read-only Junk-folder adapter**, using an injected token callback (no OAuth UI or token persistence): verifies `/me` account ID using the same token as the folder/page requests, resolves that account's well-known Junk folder, parses bounded message pages, rejects unsafe pagination links/redirects and reports throttling without exposing tokens. Production callers must use its no-auto-redirect client factory (or equivalent safe handler). Nullable recipient-state parsing distinguishes absent/invalid To from an explicitly empty To list. A pure, per-account opt-in preview applies the portable Junk rules and returns IDs/counts/sanitized reason categories without moving any mail; the caller must supply only messages from the verified account's Junk folder. Fake HTTP/data tests only; no live account accessed.
- Gmail **read-only Inbox adapter** with injected token callback: checks account profile email, lists bounded Inbox message IDs and fetches metadata or bounded plain-text MIME parts; constrained paths/tokens, no write requests. Use its no-redirect HttpClient factory in production; arbitrary injected auto-redirect clients are not secure. Fake HTTP tests only; no live account accessed.
- Provider-independent deletion *decision policy*: ordinary Delete outside Trash plans move-to-trash; Delete in Trash or Shift+Delete requires explicit permanent-delete confirmation; queued actions bind account/message/folder/revision and refuse stale state. This is pure logic and **cannot perform any actual deletion**.
- A **standalone, not yet integrated** offline plain-text cache contract for caller-verified Microsoft/Gmail accounts. Account-scoped snapshots support upsert/list/get/local delete and restart round trips with size limits, SHA-256-derived file names and Unix-private files/directories. It stores local content **unencrypted** (no OAuth tokens), provides no sync/attachment fetching/UI, and is not suitable for untrusted shared directories or adversarial concurrent filesystem mutation.
- Archive paths may be passed on the command line for repeatable local/headless testing; UI event guard prevents stale selection results and detaching a store while a queued read begins. A selected-folder **header-only** read-only search matches sender, recipients or subject (max 500 results); it is not the required cross-store full-text index. Selected messages without attachments or HTML-only content can now be exported as a conservative text/plain UTF-8 EML to a **new file**; unsupported messages fail closed rather than silently dropping content. The legacy PstCore.EmlExport writer is not used by this UI.
- Portable OAuth 2.0 desktop **PKCE primitives** for Microsoft personal and Google: random state/verifier and SHA-256 challenge, strict loopback redirect/state/replay checks and fake-HTTP token exchange against pinned endpoints. A separate single-use callback listener binds to an ephemeral 127.0.0.1 port, rejects malformed/incorrect Host requests and returns a generic browser response. The Microsoft authorization URI uses `localhost` to match Microsoft's variable-port desktop redirect registration; Google uses `127.0.0.1`. The coordinator starts capture before the system-browser launch and passes the accepted callback to the PKCE exchange. A Linux libsecret adapter implements the secret-store contract, requiring an unlocked persistent default collection distinct from the session collection and failing closed when unavailable. It runs off the UI thread and never passes tokens in command arguments or writes them to ordinary files. Its availability check now gates account setup. The owner completed a browser sign-in and the build process later verified a saved refresh token through the persistent keyring.
- Google authorization requests offline access; Microsoft account setup requests `offline_access`, `User.Read` and `Mail.Read`, while Google requests Gmail read-only access. Bounded refresh requests use pinned provider token endpoints and a caller-verified account handoff. Fake HTTP and secret-store tests cover token rotation, retaining a token when no replacement is issued, and withholding a new access token when rotated-token storage fails. The Microsoft folder views now refresh through the saved keyring token.
- The desktop **Account setup** window offers provider selection and browser sign-in without asking users for an application ID. It reads OpenOutlook-owned public client IDs from an optional file beside the executable and disables sign-in with a clear explanation when a provider is not configured. The project owner supplied a Microsoft client ID, included only in the owner’s ignored local build configuration; Google remains unconfigured. A fresh GitHub checkout ships only an empty example configuration. It launches only the pinned provider authorization page, verifies Graph `/me` ID or Gmail profile email, asks for explicit identity confirmation and saves the refresh token in the Linux keyring. A private JSON metadata registry stores provider, verified identity and public client ID but no token; it supports up to two accounts per provider and four total, plus local reconnect/disconnect. Keyring and metadata storage are checked before browser authorization. The owner's screenshot showed a successful Hotmail connection with its token in the keyring. A headless live check verified that the saved keyring token refreshes and reads the same Microsoft account.
- Saved Microsoft accounts now appear in the main sidebar after restart. The sidebar now lists visible Microsoft folders and child folders, with unread counts; it keeps an Inbox shortcut available while listing loads. Selecting a folder uses the keyring refresh token to obtain an access token, verifies Graph `/me` against the saved account ID, then requests folder counts and at most the newest 50 messages. Selecting a message requests its body and shows HTML through an inert native-text preview with headings, emphasis, paragraphs and lists; remote images and active content stay blocked. A plain-text toggle is available, and a missing body falls back to the bounded preview. PST HTML-only messages use the same preview. Refresh reloads the selected folder. Folder traversal is capped at 200 entries and 10 levels, with bounded pages and same-origin pagination checks. All requests are read-only with bounded responses, a no-redirect transport, cancellation and stale-selection guards. Access tokens are kept only in memory and reused until near expiry; a new app session refreshes from the persistent keyring token rather than reopening browser sign-in. Synthetic Graph and saved-token restart tests pass. A headless check with the owner-authorized account refreshed the saved token, listed mail folders and messages, and fetched an HTML body without printing its contents. A headless Avalonia interaction then opened that message and visually verified the native rich-text preview and paragraph spacing. The original live list request failed with HTTP 400 because it requested the unsupported `size` property; removing that property fixed the live listing. Microsoft Graph v1.0 has no message size field, so the Size column is blank for live mail. This is an online preview, not background sync or an offline mailbox.
- Automated tests and headless Avalonia screenshot smoke check using Xvfb (`-extension GLX` in this environment), including an actual folder and plain-text message preview from the ~2.6 GB sample. Headless checks verify the cleaned-up folder tree, populated sizes, paperclip heading, column sorting/dragging, date grouping and restoration, and a rapid message-to-folder switch without stale preview content.
- A self-contained, single-file Linux x64 executable is built at `publish/linux-x64/OpenOutlook.Desktop`, with a portable tar archive at `publish/OpenOutlook-linux-x64.tar.gz`. The published binary launched headlessly without a system .NET runtime and opened the 2,690-message supplied folder read-only. It has not been validated on a clean Ubuntu installation or packaged as an installer.

## Commands

```bash
dotnet restore OpenOutlook.sln -p:NuGetAudit=false --ignore-failed-sources
dotnet test OpenOutlook.sln --no-restore
dotnet run --project src/OpenOutlook.Desktop/OpenOutlook.Desktop.csproj
# opt-in read-only private sample test:
OPENOUTLOOK_TEST_PST="$PWD/rmarrash_2.pst" dotnet test OpenOutlook.sln --no-restore
```

If headless, use `xvfb-run -a -s '-screen 0 1440x900x24 -extension GLX'` before the app command. Xvfb on this host failed with default GLX due to a graphics-driver crash; disabling GLX allowed the smoke launch. Current suite: 240 tests passing (including bounded PST reads, text-only EML export, account connection, safe HTML preview, Graph folder traversal and message reading). Headless restart with isolated synthetic account settings confirmed the saved account and Inbox appear and that an unavailable keyring produces a safe error. Gmail's adapter keeps the same bearer token throughout each verified read operation; account verification and subsequent pages cannot silently switch token. A local NuGet vulnerability-cache permission problem may produce `NU1900` audit warnings during build; restore with `-p:NuGetAudit=false` for development, but do not treat this as a completed dependency vulnerability audit.

## Not implemented / release gates

- The PST message table has the requested sortable, movable columns, date groups, and unread counts. Final visual styling remains. The 2,690-message sample renders headlessly; full UI latency on larger archives and repeated rapid folder switching still need broader measurement.
- Complete live verification of a real persistent-keyring store/delete round trip and clean Ubuntu validation. Register the OpenOutlook-owned Google desktop OAuth application and supply its public client ID. A headless live mailbox check now confirms token refresh, account identity, folder discovery, an Inbox page and a non-Inbox folder page. A test implementation using cached Tmds.DBus.Protocol 0.95.1 was **removed** after it caused Avalonia 11.2.3 X11 startup TypeLoadException (Avalonia resolves 0.20.0). Avalonia 11.2.3 resolves Tmds.DBus.Protocol 0.20.0, which has a [published security advisory](https://osv.dev/vulnerability/GHSA-xrw6-gwf8-vvr9); a patched 0.21.3 compatibility trial could not restore due to this session's read-only external NuGet cache. The native libsecret adapter avoids that dependency. Microsoft/Gmail mailbox write actions, full Gmail mail adapter beyond bounded Inbox/plain-text reads, mail sync/integrated offline cache, composing/sending, offline queue, folder creation/organization, search, notifications, provider attachment export, full-fidelity EML with attachments/HTML and folder export, a complete isolated HTML renderer with layout/inline-image controls, and printing. Graph's internet headers/identity mappings and Gmail MIME/label semantics must be confirmed with authorized live account tests before enabling actions or cleaning.
- Attachment export now bounds declared block sizes and heap reads before allocation, but still buffers permitted data and has not been proven against all malformed PSTs; a streaming reader and method/size/identity validation across real attachment variants remain. Only by-value PST attachments have an export path, and synthetic export tests do not establish fidelity of every PST attachment type. Export now chooses a directory instead of using a SaveFilePicker, avoiding provider-side pre-export target truncation, but pathname checks cannot fully close concurrent symlink-directory replacement races against adversarial local processes. Broader Options sections, compose scaling and a full ribbon remain; the appearance dialog and responsive panes are headless-checked.
- Integrated Junk Cleaner account adapter/scheduler/GUI *apply* import/audit; the UI can preview a selected legacy config but cannot yet apply it to a connected account, and nothing cleans mail yet.
- PST editing, folder writes, message ingestion, transfer and actual provider-backed permanent delete (only a pure decision policy exists). Existing copied core's limited write routines are not called by this prototype. All three archive write tests and classic Outlook interoperability remain mandatory before a release.
- 4 GB PST validation remains unverified; owner agreed work may proceed with the supplied ~2.6 GB fixture for now.
- No installer or clean-machine distribution validation yet. The owner completed Hotmail sign-in and a headless live check verified saved-token refresh and Inbox listing; the HTML preview, plain-text switch, folder tree and Sent Items browsing were checked in headless UI runs.

Never commit private PSTs, logs, account tokens or real message contents. Never test write operations on the original supplied archives.
