# OpenOutlook implementation status

This is a **development prototype, not the approved first release**. The full requirements and release gates remain in `PRODUCT_REQUIREMENTS.md` and `DESIGN_SPEC.md`.

## Implemented now

- Reproducible .NET 8 solution with Avalonia 11.2.3 desktop shell.
- Copied owner's `PstCore` source into `src/PstCore`, no private archives or build outputs.
- Read-only PST archive open/detach, folder list, message summaries and escaped plain-text body preview. A selected by-value attachment can be exported to a **new** local file with strict filename/size checks, a private 0600 file mode on Unix, an atomic temporary-file move and no overwrite; it never modifies the archive. All reader work runs outside the UI thread and is serialized; source archives are never opened writable. Folder-scanning is still eager and large archives may take time. The export path now calls a bounded PST reader that checks declared external-block sizes before allocating and limits the message/attachment heaps to 1 MiB each; it accepts cancellation between block reads and fails closed on ambiguous attachment subnodes. It still buffers permitted attachment bytes in memory and has not been fidelity-tested against all supplied attachment variants.
- Persistent light/dark theme, a four-color high-contrast accent palette and text-size controls for main navigation, message list and reading pane (preferences stored in XDG config); rudimentary Outlook-like three-pane layout. Preferences do not yet scale every toolbar/compose control or provide a complete Options dialog.
- Portable junk sender/optional-rule matcher plus per-account opt-in settings, durable JSON storage and explicit legacy configuration preview/import; UI now offers a **read-only legacy config preview** showing counts/rule summary without revealing keyword strings or enabling cleaning. **Not connected to any live account**, never moves/deletes mail.
- Microsoft Graph **read-only Junk-folder adapter**, using an injected token callback (no OAuth UI or token persistence): verifies `/me` account ID using the same token as the folder/page requests, resolves that account's well-known Junk folder, parses bounded message pages, rejects unsafe pagination links/redirects and reports throttling without exposing tokens. Production callers must use its no-auto-redirect client factory (or equivalent safe handler). Nullable recipient-state parsing distinguishes absent/invalid To from an explicitly empty To list. A pure, per-account opt-in preview applies the portable Junk rules and returns IDs/counts/sanitized reason categories without moving any mail; the caller must supply only messages from the verified account's Junk folder. Fake HTTP/data tests only; no live account accessed.
- Gmail **read-only Inbox adapter** with injected token callback: checks account profile email, lists bounded Inbox message IDs and fetches metadata or bounded plain-text MIME parts; constrained paths/tokens, no write requests. Use its no-redirect HttpClient factory in production; arbitrary injected auto-redirect clients are not secure. Fake HTTP tests only; no live account accessed.
- Provider-independent deletion *decision policy*: ordinary Delete outside Trash plans move-to-trash; Delete in Trash or Shift+Delete requires explicit permanent-delete confirmation; queued actions bind account/message/folder/revision and refuse stale state. This is pure logic and **cannot perform any actual deletion**.
- Archive paths may be passed on the command line for repeatable local/headless testing; UI event guard prevents stale selection results and detaching a store while a queued read begins. A selected-folder **header-only** read-only search matches sender, recipients or subject (max 500 results); it is not the required cross-store full-text index. Selected messages without attachments or HTML-only content can now be exported as a conservative text/plain UTF-8 EML to a **new file**; unsupported messages fail closed rather than silently dropping content. The legacy PstCore.EmlExport writer is not used by this UI.
- Portable OAuth 2.0 desktop **PKCE primitives** for Microsoft personal and Google: random state/verifier and SHA-256 challenge, strict loopback redirect/state/replay checks and fake-HTTP token exchange against pinned endpoints. A separate single-use loopback-only callback listener binds to an ephemeral 127.0.0.1 port, rejects malformed/incorrect Host requests and returns a generic browser response. An offline-tested coordinator starts capture before an injected system-browser launch and passes the accepted callback to the PKCE exchange. No actual browser launch from the desktop, token refresh/keyring storage or connected mail account yet. A fail-closed secret-store interface rejects writes when no compatible persistent keyring backend is configured; no plaintext fallback exists.
- Automated tests and headless Avalonia screenshot smoke check using Xvfb (`-extension GLX` in this environment), including an actual folder and plain-text message preview from the ~2.6 GB sample.

## Commands

```bash
dotnet restore OpenOutlook.sln -p:NuGetAudit=false --ignore-failed-sources
dotnet test OpenOutlook.sln --no-restore
dotnet run --project src/OpenOutlook.Desktop/OpenOutlook.Desktop.csproj
# opt-in read-only private sample test:
OPENOUTLOOK_TEST_PST="$PWD/rmarrash_2.pst" dotnet test OpenOutlook.sln --no-restore
```

If headless, use `xvfb-run -a -s '-screen 0 1440x900x24 -extension GLX'` before the app command. Xvfb on this host failed with default GLX due to a graphics-driver crash; disabling GLX allowed the smoke launch. Current suite: 166 tests passing (including synthetic bounded data-tree and text-only EML export tests). Gmail's adapter keeps the same bearer token throughout each verified read operation; account verification and subsequent pages cannot silently switch token. A local NuGet vulnerability-cache permission problem may produce `NU1900` audit warnings during build; restore with `-p:NuGetAudit=false` for development, but do not treat this as a completed dependency vulnerability audit.

## Not implemented / release gates

- Complete Microsoft and Google OAuth sign-in (desktop system-browser launch, refresh, OS-keyring token storage and account onboarding); the tested coordinator is not yet wired into a real account setup flow. The desktop's Account setup button explicitly explains the disabled state rather than attempting a sign-in without secure persistence. A test implementation using cached Tmds.DBus.Protocol 0.95.1 was **removed** after it caused Avalonia 11.2.3 X11 startup TypeLoadException (Avalonia resolves 0.20.0); keyring persistence remains a release gate. No real keyring item or account was accessed. Avalonia 11.2.3 resolves Tmds.DBus.Protocol 0.20.0, which has a [published security advisory](https://osv.dev/vulnerability/GHSA-xrw6-gwf8-vvr9); a patched 0.21.3 compatibility trial could not restore due to this session's read-only external NuGet cache. Do not use the unpatched dependency for a new keyring adapter; fail closed until a compatible patched backend is tested. Microsoft/Gmail mailbox write actions, full Gmail mail adapter beyond bounded Inbox/plain-text reads, mail sync/cache, composing/sending, offline queue, labels/folders, search, notifications, provider attachment export, full-fidelity EML with attachments/HTML and folder export, safe HTML rendering and printing. Graph's internet headers/identity mappings and Gmail MIME/label semantics must be confirmed with authorized live account tests before enabling actions or cleaning.
- Attachment export now bounds declared block sizes and heap reads before allocation, but still buffers permitted data and has not been proven against all malformed PSTs; a streaming reader and method/size/identity validation across real attachment variants remain. Only by-value PST attachments have an export path, and synthetic export tests do not establish fidelity of every PST attachment type. Export now chooses a directory instead of using a SaveFilePicker, avoiding provider-side pre-export target truncation, but pathname checks cannot fully close concurrent symlink-directory replacement races against adversarial local processes. Complete UI scaling (including toolbar/compose), an Options dialog and full ribbon; main-pane appearance controls and persistence are implemented and headless-checked.
- Integrated Junk Cleaner account adapter/scheduler/GUI *apply* import/audit; the UI can preview a selected legacy config but cannot yet apply it to a connected account, and nothing cleans mail yet.
- PST editing, folder writes, message ingestion, transfer and actual provider-backed permanent delete (only a pure decision policy exists). Existing copied core's limited write routines are not called by this prototype. All three archive write tests and classic Outlook interoperability remain mandatory before a release.
- 4 GB PST validation remains unverified; owner agreed work may proceed with the supplied ~2.6 GB fixture for now.
- No installation/publish package yet; no live account sign-in has been attempted.

Never commit private PSTs, logs, account tokens or real message contents. Never test write operations on the original supplied archives.
